# 3) Business rules penting & concurrency

- **Slot locking**: saat user memilih slot dan tekan Book, server membuat booking dalam 1 DB transaction memeriksa tidak ada booking lain overlapping untuk `therapist_id` & `scheduled_at` → jika ada, kembalikan error “slot sudah diambil”.

- **Timeout reservation**: jika booking dibuat `pending` dan belum dibayar atau belum dikonfirmasi dalam X menit, status auto `cancelled`.

- **Idempotency**: client harus mengirim `client_request_id` untuk menghindari double booking saat retry.

- **Cancel rules**: mis. free-cancel 24 jam sebelum; refund policy stored di config.

# 4) Payment (QRIS) — rekomendasi & placeholder

Karena kamu ingin sistem sederhana, rekomendasi alur pembayaran minimal:

- **Pilihan**: QRIS via local payment gateway (Midtrans, Xendit, DOKU, iPaymu, atau gateway bank).

- **Alur sederhana**:
  
  1. Client `/payments/create` → server buat record `payments` (status created) dan minta order ID ke gateway.
  
  2. Gateway balas `payment_url` atau `qr_string`. Tampilkan ke user (QR atau link).
  
  3. User bayar. Gateway panggil `POST /api/payments/webhook` di server kamu saat transaksi `paid`.
